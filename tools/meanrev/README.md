# 型1: 短期売られすぎリバウンド戦略の検証モジュール

**これは既存のミネルヴィニ式スクリーナーとは別のツールです。**

既存側のコード・パラメータ・フォワード検証中のロジックには一切触れません。
両者は前提が正反対(強い銘柄のトレンド継続 vs 一時的に売られた銘柄の平均回帰)で、
同居させられないためです。

| | ミネルヴィニ式(既存) | 型1リバウンド(ここ) |
|---|---|---|
| 買う対象 | 強い銘柄 | 一時的に売られた銘柄 |
| 想定 | トレンド継続 | 平均回帰 |
| 損益構造 | 低勝率・大テール依存 | 高勝率・小利益 |
| 保有 | 10〜15日 | 数日 |

## 既存から借りているもの

`data/audit_cache/` の行列を **読み取り専用で** 使います。書き込みません。
無ければ先に既存側で生成してください:

    python tools/audit_thresholds_long.py --stage build
    python tools/audit_thresholds_long.py --stage feat

借りる行列: `close` `high` `low` `volume` `ma200` `h20` `atr` `dates` `codes`

型1固有の中間データは `data/mr_cache/` に置きます(既存と混ざらない)。

## 前提(2026-08-19 にユーザーと決めたもの)

- **コスト 片道0.15%(往復0.3%)** を最初から全数字に入れる。後から入れると結論がひっくり返るため
- **流動性下限は 1億 / 3億 / 10億円 を横並びで測る**。既存の1億をそのまま引き継がない
- **200日線の傾きの閾値も引き継がない**。0% / 3% / 5% を独立に測る
- **決算跨ぎはまず跨ぐ前提で測る**(素の形を先に見る)
- **エントリーは引成**(シグナル判定日の終値で買う)。イグジットはH日後の終値
- **ストップ安張り付きは除外**(拾えないものを拾ったことにしない)

## 実行

    python tools/meanrev/run.py --stage build      # data/mr_cache/ を作る(数分)
    python tools/meanrev/run.py --stage baseline   # 無条件買いの期待値
    python tools/meanrev/run.py --stage signals    # 4系統のシグナル横並び

## 判定の作法

log.md「検証結果を採用してよいかの判定」の4条件をそのまま適用します。
特に **±2の幅(期待Rのばらつき2つぶん)** を全数字に併記し、
比較相手がその幅の中に入るなら「差がある」とは書きません。

なお本件は初回イグジットに損切りを入れない(固定日数のみ)ため、
条件2の「5本のストップ定義」は **分母を5通りに変えているだけ** で、
偶然でない証拠にはなりません。判定は条件1・3・4に寄せます。
